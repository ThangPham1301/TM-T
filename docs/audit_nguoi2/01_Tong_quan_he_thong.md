# Tổng quan hệ thống phục vụ báo cáo Người 2

## 1. Phạm vi và cách đọc kết quả

Báo cáo này là kết quả rà soát tĩnh repository tại thời điểm lập báo cáo. Không chạy chương trình, migration, test tích hợp và không gọi dịch vụ ngoài. Vì vậy:

- **ĐÃ TRIỂN KHAI**: tìm thấy mã nguồn hoặc migration thực thi chức năng; không đồng nghĩa đã triển khai production hay đã nghiệm thu end-to-end.
- **CHỈ CÓ THIẾT KẾ**: chỉ tìm thấy requirement, OpenAPI, protobuf, ADR, mock hoặc tài liệu.
- **CHƯA TÌM THẤY**: chưa thấy implementation trong phạm vi repository đã đọc; không phải bằng chứng chắc chắn chức năng không tồn tại ở repository/hệ thống khác.
- **ĐỀ XUẤT**: biện pháp hoặc quy trình cần nhóm xác nhận và triển khai.

Repository tự mô tả kiến trúc microservices, event-driven và database-per-service (`README.md:6`, `README.md:71`). Tuy nhiên README tổng có nội dung cũ: mô tả gateway theo nhiều lựa chọn công nghệ (`README.md:69`), trong khi cấu hình thực tế là Kong DB-less (`services/api-gateway/config/kong.yml:1`, `services/api-gateway/config/kong.yml:7`). Khi có mâu thuẫn, báo cáo ưu tiên mã và cấu hình hiện tại.

## 4. Chức năng có bằng chứng triển khai

- **ĐÃ TRIỂN KHAI — đăng ký**: request có validation email, tên, mật khẩu 12–128 ký tự và idempotency key (`services/identity-service/src/main/java/com/hvduong/identity/dto/request/RegistrationRequest.java:13`, `services/identity-service/src/main/java/com/hvduong/identity/dto/request/RegistrationRequest.java:23`, `services/identity-service/src/main/java/com/hvduong/identity/dto/request/RegistrationRequest.java:27`); orchestrator tạo principal PENDING, gọi Keycloak ngoài transaction, rồi finalize/outbox (`services/identity-service/src/main/java/com/hvduong/identity/application/registration/impl/RegistrationOrchestrator.java:93`, `services/identity-service/src/main/java/com/hvduong/identity/application/registration/impl/RegistrationOrchestrator.java:104`, `services/identity-service/src/main/java/com/hvduong/identity/application/registration/impl/RegistrationOrchestrator.java:120`).
- **ĐÃ TRIỂN KHAI — đăng nhập/session**: Web OIDC dùng state, nonce, PKCE S256 (`apps/web-user/src/lib/auth/oidc.ts:132`, `apps/web-user/src/lib/auth/oidc.ts:134`), kiểm token và callback (`apps/web-user/src/lib/auth/oidc.ts:147`, `apps/web-user/src/lib/auth/oidc.ts:149`) và đặt token trong cookie HttpOnly (`apps/web-user/src/lib/auth/oidc.ts:113`, `apps/web-user/src/lib/auth/oidc.ts:116`).
- **ĐÃ TRIỂN KHAI — Profile/Address**: schema lưu customer profile và shipping address (`services/profile-service/migrations/000001_init_schema.up.sql:25`, `services/profile-service/migrations/000001_init_schema.up.sql:47`); route CRUD địa chỉ có trong router (`services/profile-service/internal/transport/http/router.go:91`, `services/profile-service/internal/transport/http/router.go:102`, `services/profile-service/internal/transport/http/router.go:105`).
- **ĐÃ TRIỂN KHAI — Catalog**: public/admin REST và checkout snapshot có code/migration (`services/catalog-service/src/main/java/com/hvduong/catalog/api/CatalogHttpController.java:40`, `services/catalog-service/src/main/resources/db/migration/V10__checkout_snapshots.sql:1`).
- **ĐÃ TRIỂN KHAI — Cart/Checkout/Order/Payment**: API và schema được nêu ở mục 2; checkout trả Location để poll operation (`services/order-service/internal/transport/http.go:255`, `services/order-service/internal/transport/http.go:272`).
- **ĐÃ TRIỂN KHAI — Inventory**: reservation/commit/release có use case và khóa theo SKU; mục tiêu chống deadlock được mô tả ngay trong code (`services/inventory-service/internal/application/usecase/reserve_stock.go:45`).
- **ĐÃ TRIỂN KHAI — Packing/Shipping**: task/package/media/tracking có schema; Shipping lấy snapshot recipient bất biến từ Order thay vì đưa PII vào packing event (`services/shipping-service/README.md:89`).
- **ĐÃ TRIỂN KHAI — Support ticket ở client/BFF**: Web có tạo ticket, đọc chi tiết, gửi message (`apps/web-user/src/services/support-service.ts:22`, `apps/web-user/src/services/support-service.ts:25`, `apps/web-user/src/services/support-service.ts:28`), nhưng upstream mặc định là Customer Extensions mock (`apps/web-user/src/app/api/support/support-handler.ts:32`).
- **ĐÃ TRIỂN KHAI — Return ở client/BFF**: Web xác thực session và trusted origin (`apps/web-user/src/app/api/returns/return-handler.ts:55`, `apps/web-user/src/app/api/returns/return-handler.ts:58`), validate request và gọi upstream (`apps/web-user/src/app/api/returns/return-handler.ts:71`, `apps/web-user/src/app/api/returns/return-handler.ts:74`).

## 6. Kết luận dùng cho Đề tài 3

Hệ thống đã có nền tảng kỹ thuật đáng kể cho bảo mật và tính toàn vẹn giao dịch: Identity tách khỏi Profile, JWT/PKCE, database-per-service, idempotency, snapshot mã hóa, inbox/outbox và state machine. Điểm cần trình bày trung thực trong báo cáo là mức trưởng thành không đồng đều: code backend lõi đã tồn tại nhưng phần lớn tích hợp production còn gated; Return/Support/Chatbot đặc biệt không được suy diễn từ UI, mock hay OpenAPI thành backend đã vận hành.
